# Capture Thought

## Purpose

Turn what the user naturally says into a note they will still understand months or years later without making them organize it first.

The goal is **not** to improve the theology, make the writing impressive, turn the idea into a sermon, or create a complex knowledge-management record.

The goal is:

> Preserve the thought the user actually had, in a clearer and more usable form.

## Default posture

Assume the user may be speaking through dictation or thinking out loud.

They may:

- repeat themselves;
- use filler words;
- start over mid-sentence;
- remember Scripture approximately rather than by chapter and verse;
- tell a long story before naming the insight;
- mix observation, emotion, application, and questions together;
- stop before reaching a conclusion.

Do not require them to clean any of this up.

## Workflow

### 1. Find the real thought

Read/listen for the central idea without forcing it into a stronger claim than the user made.

Also notice whether the material includes one or more of these natural forms:

- Scripture reflection;
- biblical connection;
- illustration or story;
- book/source insight;
- theological question;
- ministry or discipleship thought;
- sermon/teaching seed;
- personal reflection;
- prayer or conviction;
- leadership thought;
- unfinished idea.

These categories are aids for understanding, not metadata the user must see every time.

### 2. Preserve before polishing

Before editing, identify what must not be lost:

- the main insight;
- the user's level of confidence;
- important phrases that sound like the user;
- the story or setting that gave rise to the thought;
- relevant people or circumstances;
- Scripture or other sources;
- questions and tensions that remain unresolved.

If a personal story carries emotional, illustrative, or interpretive weight, preserve the story. Do not collapse it into a lesson statement.

### 3. Clarify vague references carefully

When the user vaguely remembers a Scripture passage or source, resolve it when confidence is high.

Examples:

- "the woman who kept bothering the judge" → likely Luke 18:1–8;
- "the friend who keeps knocking for bread" → likely Luke 11:5–10.

When adding a reference:

- prefer the exact passage range when reasonably clear;
- do not add a quotation unless needed;
- do not claim the user named the reference if the agent supplied it;
- if confidence is not high, write "likely" or leave the reference unresolved.

The same rule applies to books, authors, sermons, podcasts, and articles: clarify what can be clarified without guessing.

### 4. Distinguish layers when it matters

For Scripture-based thoughts, preserve the difference between:

- **Text:** what the passage explicitly says;
- **Observation/interpretation:** what the user is seeing in it;
- **Application:** what the user thinks it may mean for life or ministry;
- **Question:** what remains unresolved.

Do not mechanically create four headings in every note. Use the distinction internally and surface headings only when they improve clarity.

For outside sources, preserve the difference between:

- **Source idea:** what the author/speaker appears to be saying;
- **User response:** what the user thinks, questions, accepts, rejects, or wants to explore.

### 5. Lightly edit the spoken material

Clean:

- filler words;
- transcription errors that are obvious from context;
- empty repetition;
- false starts;
- sentence fragments that can be safely repaired;
- paragraph order when needed for readability.

Keep:

- natural first-person language;
- distinctive phrases;
- emotional honesty;
- unresolved tension;
- enough narrative detail for stories to remain vivid;
- repetitions that are meaningful rather than merely verbal clutter.

Do not turn ordinary language into polished devotional language.

Do not introduce phrases such as "This powerful truth reminds us..." unless the user actually speaks that way.

### 6. Give the thought a searchable title

Choose a title that captures the recognizable idea rather than the format.

Good examples:

- Persistence in Prayer When Nothing Is Changing
- David's Security Exposed Saul's Insecurity
- The Difference Between Teaching Discipleship and Normalizing It
- What Parenting Is Teaching Me About Patient Formation

Avoid:

- Thought 1
- Bible Reflection
- Random Idea
- Journal Entry

### 7. Shape the note simply

Default to a small number of paragraphs with minimal headings.

A useful note may look like:

```md
# <Title>

<the cleaned thought in the user's voice>

## Scripture / Source
<only when relevant>

## Question I'm Still Exploring
<only when the user actually has one>

## Related Thought
<only when there is a genuinely useful connection>
```

Do not force this template. A strong note may need no subheadings at all.

### 8. Check for a related existing thought only when worthwhile

If the archive is available and the thought is substantial, perform a lightweight search for obvious overlap using the main ideas, Scripture reference, source, or distinctive phrase.

If a strong match exists:

- if this is clearly a continuation, append/update the existing note;
- if it is distinct but related, create the new note and add a simple related-thought link/reference.

If no strong match exists, create the new note.

Do not build elaborate tag taxonomies, graph structures, or metadata just because they are possible.

### 9. Save to the canonical archive

Save the finished note in the Google Drive folder:

**Thoughts and Things from God**

A distinct substantial thought normally gets its own Google Doc.

Favor the simplest folder/location that keeps it retrievable. Do not ask the user to choose a filing location unless context truly cannot resolve it.

### 10. Report briefly

After saving, tell the user what was captured and where it was saved. Keep the report short unless they ask to see the full cleaned note in chat.

## Special rules

### Preserve stories

A story is not disposable setup.

If the user says, in effect, "this thought came to me while I was sitting in a hospital room," the hospital room may be part of the meaning. Preserve it when removing it would make the reflection less understandable, less human, or less useful as a future illustration.

### Preserve uncertainty

Keep confidence at the same level the user gave it.

Examples:

- "I wonder if..." → remains exploratory.
- "I think this may mean..." → remains tentative.
- "I'm convinced..." → may be stated strongly.
- a question → remains a question unless the user later resolves it.

Never silently promote an exploration into doctrine.

### Do not invent

Never add:

- events the user did not describe;
- feelings the user did not express;
- motives for other people;
- quotations the user did not provide or that were not verified;
- theological conclusions just because they would complete the thought nicely;
- source details you cannot confidently establish.

### Do not sermonize automatically

A captured thought is not automatically:

- a three-point sermon;
- a Bible study;
- a devotional;
- a leadership framework;
- a ministry strategy.

Only develop it in those directions when the user asks.

### Do not over-format

The archive should remain pleasant to read. Prefer clear prose over excessive metadata, tables, labels, tags, nested folders, or repeated boilerplate.

## Quality check before saving

Ask internally:

1. Does this still sound like the user's thought?
2. Did I preserve the story/context that gives it life?
3. Did I accidentally make the theology stronger or more certain?
4. Did I add any detail that was not actually given or confidently resolved?
5. Did I clarify vague Scripture/source references when useful?
6. Will the user understand this note a year from now?
7. Is this simpler than it needs to be, or did I over-engineer it?

If the note fails any of these, revise before filing.
